# mcxRCServo

[English](README.md) | 日本語

**RCサーボモータ**ライブラリ（[mcx-arduino-core](https://github.com/teddokano/mcx-arduino-core)用）。

![SG90とFS90R、その後ろにFRDMボード](img/rc_servo1.jpg)

PWMピン1本でホビー用RCサーボを駆動する。**SG90**（位置決め型）と
**FS90R**（連続回転型）の2機種は、それぞれのデータシートのパルス幅を
持たせた状態ですぐ使える。

全サンプルをFRDM-MCXA153とFRDM-MCXN947の両方で動作確認済み。

## 使い方

```cpp
#include <SG90.h>

SG90 servo(PWM0);

void setup() {
  servo.range(-90, 90);   //  work in degrees
}

void loop() {
  servo.position(90);
  delay(500);
  servo.position(-90);
  delay(500);
}
```

```cpp
#include <FS90R.h>

FS90R servo(PWM0);

void loop() {
  servo.speed(1.0);   //  CCW, full speed
  delay(2000);
  servo.stop();
  delay(2000);
}
```

サンプルは3つ:

- `SG90_basic` -- サーボを動かす最小のスケッチ
- `SG90_moves` -- 位置決め型サーボを、ステップ移動・等速グライド・
  イージング付きグライド・減衰する振り子・ランダムな首振りの順に動かす
- `FS90R_rotate` -- 連続回転型サーボを両方向の全速で回し、続けて速度範囲
  全体を掃引する

サーボ自身が持つ速度は1つだけなので、それより遅い動きや形のある動きは、
最終値を1回渡すのではなく、途中の値をタイマで流し込んでスケッチ側が作る。
`SG90_moves`では小さな`glide()`ヘルパがそれをやっている。

## クラス階層

```
mcxRCServo          PWM出力と、値からパルス幅への対応付け
 |
 +- PositionServo    パルス幅が軸の角度: position()
 |   +- SG90         0.50-2.40ms, 50Hz
 |
 +- RotationServo    パルス幅が回転速度: speed(), stop()
     +- FS90R        0.70-2.30ms, 50Hz
```

`mcxRCServo`は、渡された値が何を意味するかを知らない。ユーザが決めた値の
範囲をパルス幅の範囲に写すだけである。その下の2クラスが値に意味を与え、
さらにその下の製品クラスが、実際のサーボ1機種のパルス幅を与える。

### range()

`range(left, right)`は、アプリケーションが使いたい単位を決める。サーボの
パルス幅範囲に対応付けられ、`left`が最短パルス、`right`が最長パルスになる。
位置決め型なら度、回転型ならパーセントやRPM、その他スケッチに都合のよい
単位でよい。`position()` / `speed()`に渡された値はこの範囲に丸められる。

既定値は0.0〜1.0。ただし`RotationServo`だけは-1.0〜+1.0を設定し、停止
パルスがゼロに来るようにしている。

## サーボを追加する

`PositionServo`か`RotationServo`から派生し、パルス幅をコンストラクタに
渡す。製品クラスがやることはそれだけである:

```cpp
class MG996R : public PositionServo
{
public:
  MG996R(int pwm_pin);

private:
  static constexpr double frequency_hz = 50.00;
  static constexpr double pulse_high_min_ms = 0.50;
  static constexpr double pulse_high_max_ms = 2.50;
};

MG996R::MG996R(int pwm_pin)
  : PositionServo(pwm_pin, pulse_high_min_ms, pulse_high_max_ms, frequency_hz) {}
```

パルス幅が分かっているだけのサーボなら、`PositionServo` /
`RotationServo`を直接使い、コンストラクタにパルス幅を渡せばよい。

## なぜmcx-arduino-core専用なのか

`library.properties`には`architectures=mcx`と書いてある。これは安全側に
倒しているのではなく、素のArduinoコアにはない2つのものに依存している
ためである。

**`mcxRCServo`が`Obj`を継承している。** `Obj`はmcx-arduino-coreのr01libで
全ペリフェラルドライバの共通基底となっているクラスで、その唯一の仕事は、
誰かが最初にペリフェラルオブジェクトを構築した時点でチップの
`init_mcu()`を1度だけ走らせることである。このライブラリにはそれが要る。
サーボは通常グローバルオブジェクトとして置かれ、そのコンストラクタがピンの
PWM周波数と分解能をその場で設定する -- つまり`setup()`より前、`main()`より
前に実行されるからだ。素のコアでは、その時点でハードウェアを立ち上げている
ものが何もない。グローバルコンストラクタからPWMペリフェラルに触れて安全な
のは、`Obj`を継承しているからである。

**`analogWriteFrequency()`は公式のArduino APIではない。** RCサーボは
パルスを約50Hzで繰り返す必要があるが、素の`analogWrite()`にはフレーム
レートを指定する手段がない。`analogWriteFrequency( pin, hz )`は一部の
ベンダコアが提供するde facto拡張で（Teensyのものが最もよく知られている）、
公式Arduinoは -- AVRのタイマではPWM周波数制御がきれいに実現できないため
-- これを標準化しなかった。mcx-arduino-coreはこれを持っているが、多くの
コアは持っていない。

他のコアへ移植するなら、この2つを置き換えることになる。`Obj`の継承を
やめ、PWMの設定をコンストラクタから`begin()`へ移してスケッチの`setup()`
から呼ぶこと。そして、そのコアが提供するPWM周波数の設定手段を用意する
こと。`mcxRCServo`より上 -- 各サーボのパルス幅、値の範囲の対応付け、
クラス階層 -- はただの算術であり、そのまま持っていける。

## ハードウェアについて

![信号・電源・GNDの3本をFRDMボードに配線した図](img/wiring.png)

3本の線の色はRCサーボの慣例通り。茶がGND、赤が電源、橙または黄が信号。

信号線は`PWM0`〜`PWM5`のいずれかに接続する。`analogWrite()`が駆動できる
ピンで、ボードのシルクにも印刷されている。両ボードともヘッダ上の位置は
同じなので、同じ配線・同じスケッチがどちらでも動く。違うのは名前の裏に
あるMCUのピンだけである。

| ピン名 | FRDM-MCXA153 | FRDM-MCXN947 |
|---|---|---|
| `PWM0` | P3_11 | P2_3 |
| `PWM1` | P3_10 | P2_2 |
| `PWM2` | P3_9  | P2_5 |
| `PWM3` | P3_8  | P2_4 |
| `PWM4` | P3_7  | P2_7 |
| `PWM5` | P3_6  | P2_6 |

`PWM0`〜`PWM5`はFlexPWMのサブモジュールを2本ずつ共有していて
（`PWM0`/`PWM1`、`PWM2`/`PWM3`、`PWM4`/`PWM5`）、ペアはperiodレジスタが
共通である。したがって片方のピンの周波数を設定すると、もう片方の周波数も
変わる。ここで扱うサーボはどれも50Hzなのでペアで使う分には問題ないが、
周波数の違うものとペアを共有させてはいけない。

SG90のサンプルは、上の図の通りサーボをボードから給電した状態で動作確認
した。位置決め型は実際に動いている間しか電流を引かないので、無負荷の
SG90が短時間動く分にはボードの供給範囲に収まる。

**FS90Rには別電源が要る。** FRDM-MCXA153でボードの5Vから駆動したところ、
レールが落ち込んでPCとのUSB接続が不安定になった。連続回転型は回せと言われた
間ずっと運転電流を引き続け、反転のたびに突入電流が乗るので、位置決め型とは
比較にならないほど電源に負担をかける。4.8V〜6Vの別電源を用意し、GNDを共通に
すること。他のボードなら余裕がある、とは考えないほうがよい。

SG90でも、負荷がかかる場合や2個目を足す場合は同様である。ストール電流は
FS90Rで650mA、SG90で数百mAに達し、USBからボードの5Vレールに供給される分を
超える。ストールに至るずっと手前から、電圧の落ち込みはボード自身の電源にも
及ぶ。

信号線の入力しきい値は、どちらのデータシートにも記載がない。両サーボとも
5V電源で動作させながらボードの3.3Vロジックレベルで駆動しており、両ボード
での動作確認もこの条件で行った。

## 補足

どちらのサーボもアナログ型で、データシートにフレームレートの記載はない。
ここで使っている50Hzは、アナログRCサーボで一般的な値である。

`analogWriteResolution()`はArduino APIではグローバルな設定なので、最後に
構築されたサーボに与えられた分解能が、スケッチ中のすべての`analogWrite()`
に効く。変更する理由がなければ既定の16ビットのままでよい。
