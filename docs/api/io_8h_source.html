216 // NOTE (corrected after initial real-hardware bring-up): an earlier
217 // version of this file reused A153's physical pin numbers (P3_6..P3_11)
218 // verbatim. On N947 those pins are bare test points (TP8/TP12-18/TP31 in
219 // pin_mux.c's schematic labels), not routed to any populated header --
220 // so analogWrite() compiled and ran but drove pins nobody could reach.
221 // The real PWM-capable, header-accessible pins are P2_2..P2_7 (Arduino
222 // Shield Compatible Headers sheet, FRDM-MCXN947SH.pdf page 12), on
223 // FlexPWM1 (not FlexPWM0 -- see PwmOut.cpp for that instance-name
224 // collision too). This chip's SDK also defines bare `PWM0`/`PWM1` macros
225 // for the FlexPWM peripheral instances themselves ((PWM_Type*)PWM0_BASE /
226 // PWM1_BASE), so those two names have to be explicitly reclaimed here
227 // (#undef, matching the same technique already used in
228 // source/r01device/led/LEDDriver.h for the same collision) before they
229 // can be redefined as logical pin names -- PwmOut.cpp captures the SDK's
230 // original PWM1 meaning into its own alias before including this header,
231 // so its driver calls keep working once this redefinition is in effect.
232 // The PWM0..PWM5 -> physical pin assignment below matches the
233 // "PWM0".."PWM5" silkscreen labels printed directly on that schematic
234 // sheet's header, not physical pin order.
235 #undef PWM0
236 #undef PWM1
