168/*
169 * I3C_SDA/I3C_SCL/I2C_SDA/I2C_SCL are aliases of other names in this same
170 * table (e.g. I2C_SDA is literally "#define I2C_SDA D18" in r01lib's own
171 * io.h) -- a plain textual substitution, re-expanded wherever it's used,
172 * not an independent value. Simply leaving I2C_SDA out of this table's
173 * #undef/enum step (as tried initially) does NOT decouple it: it still
174 * expands to D18, and D18 itself gets renumbered below, so I2C_SDA would
175 * silently inherit D18's *new* small-int value regardless. Captured here,
176 * before anything below is #undef'd, so these constexprs freeze today's
177 * raw r01lib value -- then further down they're #undef'd and redefined to
178 * literally *be* these frozen constants, breaking the alias chain for
179 * good. (Found via real-hardware testing: this exact bug reappeared as an
180 * SOS panic on FRDM-MCXN947's r01lib_I3C example after the first attempt,
181 * since N947's I3C_SDA aliases MB_RX -- a renumbered name -- while A153's
182 * happens to alias a raw physical pin macro (P0_16) that was never
183 * renumbered, masking the same underlying bug there.)
184 */
185constexpr int _raw_I3C_SDA = I3C_SDA;
186constexpr int _raw_I3C_SCL = I3C_SCL;
187constexpr int _raw_I2C_SDA = I2C_SDA;
188constexpr int _raw_I2C_SCL = I2C_SCL;

302/*
303 * I3C_SDA/I3C_SCL/I2C_SDA/I2C_SCL are redefined here to the raw values
304 * frozen above, NOT given a fresh sequential enum slot like the names
305 * above -- unlike D0-D19, MB_*, SPI_*, ARD_* (all genuinely usable as
306 * ordinary pinMode()/digitalWrite() pins, or required for third-party
307 * compatibility like MOSI/MISO/SCK below), these four are only ever used
308 * as raw r01lib pin values: constructor arguments to I2C/I3C (internal
309 * arduino_i2c.cpp plumbing, unaffected either way since it never includes
310 * this header, or "Arduino_incompatible_API" examples constructing r01lib
311 * objects directly). Fixing them to their raw value means the same name
312 * means the same value everywhere, whether or not <Arduino.h> has been
313 * included -- closing off the "renumbered here, raw there" mismatch that
314 * caused two real SOS-panic bugs (Serial1 on MikroBus, and the
315 * r01lib_I3C example).
316 */
